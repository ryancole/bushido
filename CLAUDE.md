# bushido

Side-view 3D sword PvP game (1v1). C++20, Vulkan 1.3 (dynamic rendering, sync2), GLFW, vk-bootstrap, GLM, Jolt Physics, miniaudio, Dear ImGui. Dependencies come in via CMake FetchContent; the Vulkan SDK is installed at `C:\VulkanSDK\1.4.350.0`.

## Build (Windows, MSVC + Ninja)

The toolchain is pinned to MSVC via CMakePresets.json (`msvc-debug` → `build/`, `msvc-release` → `build-release/`); CMakeLists errors out on any other Windows compiler. MSVC is not on PATH; chain through vcvars64:

```
cmd /s /c '"C:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat" && cmake --preset msvc-debug && cmake --build --preset msvc-debug'
```

Run: `build\bushido.exe`. Boots to a main menu (Play / Quit, mouse or ImGui keyboard nav); Play opens a character-select screen (mouse-driven, three stages: hovering a tile previews stats, clicking a fighter opens the weapon row, clicking a blade opens the battleground row, clicking a level locks everything and starts the match against a randomly drawn opponent — fighter and weapon both random; the level is the player's pick). Esc backs out one level (match → menu, select stage → previous stage → menu, menu → quit). In a match — WASD moves in the ground plane (W/S = depth), Space jumps, holding **Left Shift blocks** (guard up, slower walk), holding **Left Ctrl crouches** (smaller profile, slower walk, no jumping, swings ride a lower lane), and the mouse attacks: **left-tap = normal swing, left hold-and-release = heavy swing, right press = quick jab**; the opponent is bot-driven (see `src/bot`).

VS Code: `.vscode/` has a default build task (Ctrl+Shift+B), a `configure` task, and F5 debug configs (`cppvsdbg`). IntelliSense reads `build/compile_commands.json`.

## Layout

- `src/main.cpp` — game loop (fixed 120 Hz timestep), input reading, scene drawing. Owns the `AppState` machine (`Menu` → `CharacterSelect` → `Playing`, Esc backs out one level): menus freeze the sim (accumulator zeroed) but keep drawing the arena behind the UI; ImGui menu code (`setupMenuStyle`/`drawMainMenu`/`drawCharacterSelect` — restyled colors, Georgia from the system fonts when present, per-widget sizing via `ImGui::PushFont(nullptr, size)`) lives here, built between `beginFrame`/`endFrame`. The select screen is single-player and mouse-driven: a tile row where hovering previews a character's stats in the panel below (crimson frame follows the preview) and clicking picks it; the opponent's roster index is drawn at random (`std::mt19937` in main). `Game` is heap-owned and **rebuilt from the two (character, weapon) index pairs on pick** — every match starts fresh; the initial instance is just the diorama behind the menu. Attack input: LMB attacks on **release** — a tap is the light swing, a hold ≥ `kHeavyHoldTime` (0.28 s) charges the heavy — and RMB jabs on press; the resulting `AttackKind` is latched alongside the press so it survives zero-step frames. On match start the button latches are re-seeded from live state and a still-held LMB is flagged suppressed so even the picking click's later release doesn't become a swing (`startMatch` lambda, shared by pick and rematch). In-match HUD: `drawBloodBars` paints a blood bar per fighter into the foreground draw list (top corners, draining outward). When `Game::over()`, the bot's input is zeroed (the human keeps control) and after a 1.2 s beat `drawWinOverlay` shows VICTORY/SLAIN with Rematch (same pairing, fresh `Game`) and Character Select buttons.
- `src/characters/` — the selectable roster, one file per fighter (same shape as `src/levels/`). `character.hpp` is the whole public surface (`CharacterStats`, `CharacterDef`: stable `id` slug, name, `SamuraiColors`, authored 0–5 select-screen ratings, `kCharacterCount`, `characterDef(index)`); `character.cpp` is just the index → def table, whose order is the select-screen order *and* the netplay index, so rows are appended, never reordered; `registry.hpp` declares each fighter's namespace. Each fighter owns one .cpp (`ronin.cpp`, `shinobi.cpp`, `oni.cpp`, `kensei.cpp`) holding its `kDef` in C++20 designated-initializer form plus the design note for what it trades away — a character carries no code of its own today, so a namespace holds nothing but `kDef`; per-fighter hooks (move sets, model tweaks) would go beside it the way `levels/registry.hpp` carries draw/obstacles/water. Adding one: new .cpp, a namespace in `registry.hpp`, a row in `character.cpp`, `kCharacterCount`++. All stats are compile-time constants and a match is fully described by two (character, weapon) index pairs plus a level index — **multiplayer-ready by construction**: peers would only ever exchange indices/ids, never stats, keeping the sim deterministic across machines. Current four: Ronin (baseline — the old global constants), Shinobi (fast/light), Oni (slow, huge knockback, heavy), Kensei (longest reach). Stats: moveSpeed, jumpVelocity, windup/active/recovery times, reach (blade tip from shoulder — drives both the gameplay sweep and the drawn blade length via `SamuraiPose::reach`), knockback dealt, weight (divides knockback/pop received).
- `src/levels/` — the battleground roster, one file per level. `level.hpp` is the whole public surface (`LevelDef`, `LevelObstacle`, `LevelWater`, `kLevelCount`, the five `levelX(index)` accessors), same compiled-in-roster contract as characters/weapons; `level.cpp` is nothing but the index → implementation dispatch over a `LevelEntry` table; `registry.hpp` declares each level's namespace (`def` and `draw` required, `obstacles`/`ground`/`water` optional — a null hook means "none", which is why Dojo only fills in two); `scenery.hpp` holds the shared `box`/`hash01` draw helpers. Each battleground owns one .cpp (`dojo.cpp`, `hanami.cpp`) holding its def, its solid geometry, **and** its drawing together — the scenery is bespoke procedural code, so splitting data from drawing would only fracture a level across two places. Adding one: new .cpp, a namespace in `registry.hpp`, a row in `level.cpp`'s table, `kLevelCount`++. Levels share the arena depth but **author their own width** (`LevelDef::arenaHalfWidth` — Dojo the baseline 12, Hanami widened to 16; `Game` bakes it in as `arenaHalfWidth()` and hands it to `Physics` for side-wall placement); a level contributes scenery plus **solid obstacles**: `levelObstacles(index)` is a deterministic once-built list of `LevelObstacle` boxes (Hanami's bank stones; Dojo has none) that `Game`'s ctor feeds to `Physics` as static colliders *and* `drawLevel` draws from — one list, so what you see is exactly what you collide with (stones near the fighter spawns are skipped at generation). `drawLevel(renderer, index, time)` draws the scenery (called first by main's `drawScene`, so gameplay draws on top), with all ambient motion a pure function of `time` (deterministic `hash01` scattering, no stored state). Current two: Dojo (the original dark slab + pillars — flat, dry, nothing solid) and Hanami (grass banks around a genuinely carved stream at x = −6 — clear of player 1's spawn at −3: `levelGround(index)` replaces the default flat physics slab with per-level boxes (two banks + a 0.35 m-deep bed, under the 0.4 m step-up so fighters wade shin-deep and climb out), and `levelWater(index)` describes the water volume — `Physics::step` gives debris inside it buoyancy + drag toward the 0.55 m/s +z current via Jolt's `ApplyBuoyancyImpulse` (pieces kept awake so the drift never stalls), so severed limbs/heads bob off downstream; `Game::addBloodMark` drops marks inside the water footprint (blood washes away) and stream-bed debris impacts skip the smear/droplet burst. Ripple glints scroll +z matching the current; stone-lined banks, sakura trees dispersed through the playfield — upright, their trunks in the obstacle list, canopy/branch cosmetic — plus a leaning collider-free backdrop rank past the playable depth, looping fall of tumbling petals, and the **shinobi no ie** on the widened left flank: an authored `HouseBox` list — draw + colliders from one table — with a 0.36 m engawa platform fighters step onto (under the 0.4 m step-up), solid back/left walls, open front and right side, solid two-tier roof, flush cosmetic shoji screens). The picked level index rides in main's `matchLevel` (beside the loadout indices, so Rematch keeps the arena) and is baked into `Game` at construction (`Game::level()` — `drawScene` reads it, which also picks the diorama behind the menus).
- `src/weapon.hpp/.cpp` — the sword loadout armory (`WeaponDef`), same compiled-in-roster contract as characters. Weapons modify the wielder rather than replace their stats: `swingScale` multiplies windup/active/recovery, `reachBonus` adds meters of blade, `knockbackScale` multiplies shove dealt, `damage` scales the torso-hit and sever blood costs (never the beheading — the execution empties the pool with any blade), `bladeWidth` is a visual-only thickness cue (`SamuraiPose::bladeWidth`). Current three: Katana (neutral — all 1×, so character tuning is unchanged), Wakizashi (fast, short, cheap cuts), Odachi (slow, long, ruinous). `Game` bakes weapon into character once in its ctor; everything outside the sim (bot, rendering) reads the resolved numbers via `Game::stats(i)`, never the raw roster.
- `src/game.hpp/.cpp` — simulation: two `Player`s moving freely in the x/z ground plane. Gameplay stays authored (Game decides velocities: move speed, jump, gravity integration into `vy`, knockback — the per-fighter numbers come from each player's `CharacterDef` with their `WeaponDef` applied, both picked at select time); collision is delegated to `Physics` per fixed step, which returns resolved position + grounded. Sword combat: `AttackState` machine (windup → active → recovery, durations per character) crossed with an `AttackKind` (light / heavy / jab) picked at press time — `kAttackTuning` in game.cpp scales the wielder's resolved phase times, damage, knockback, and hitstun per kind and sets the blade arc (light/heavy chop overhead-to-front, the jab snaps a short arc to horizontal; angles mirrored in samurai.cpp's `swordArmAngle`). The jab pierces instead of cutting: `canSever = false` downgrades any limb/head connect to a torso-grade hit — no dismemberment, no execution. **Blocking**: holding `PlayerInput::block` raises the guard (`Player::blocking`; needs an arm, standing, not mid-swing — the model holds the blade at the foe via `SamuraiPose::blocking`), scales walk speed by `kBlockMoveScale`, and suppresses attack presses. A blocked connect (any attack from the defender's front) costs no blood and can't sever — the defender takes a short `kBlockstunTime` stagger plus `kBlockKnockbackScale` of the shove, and a `Sfx::Block` clang plays. The catch opens a **riposte window** (`Player::riposteTime`, `kRiposteWindow` scaled by the caught attack's hitstunScale — heavier blows leave longer openings; the blocker's kimono glows gold while it's live, and a clean hit taken erases it): the first attack started inside it gets `kRiposteWindupScale` on its windup (`Player::attackWindupScale`, also folded into the pose's attackT). **Crouching**: holding `PlayerInput::crouch` while grounded and upright ducks (`Player::crouching`; `Player::crouchAmount` chases it at `kCrouchRate` so the duck is a motion, not a snap): walk speed scales by `kCrouchMoveScale`, jumping is suppressed, and the whole upper body drops `kCrouchDrop` × amount — pose (samurai.cpp folds the legs, `SamuraiPose::crouch`), hurtboxes (`crouchedLimbBounds`: arm/head boxes drop, leg boxes squash toward the floor; torso box drops too), and the attacker's blade pivot all move together, so a crouched fighter is genuinely smaller and crouch-swings sweep a lower, leg-hunting lane. The physics capsule is unchanged (nothing overhead to duck under; body-blocking stays full height). Attack presses are buffered (`Player::attackBuffer`, `kAttackBufferTime`) so a click during blockstun/hitstun/recovery fires on the first able tick instead of dropping — which is what makes the riposte clickable at the clang. During active the blade is swept as a segment along the attack's arc (pure math on `Player::pos`, not Jolt queries) against per-limb AABBs (`samuraiLimbBounds` + per-limb pad) and a torso box. Any connect ⇒ hitstun + planar knockback + upward pop + interrupts the victim's swing; a limb connect also **dismembers**: the limb is flagged in `Player::severed[]`, launched as a Jolt debris body (`SeveredPiece` list, drawn by main), and stays lost for the match. The head's z pad is tight so beheading takes depth-aligning the blade lane (sword arm rides `kShoulderSide` off center); losing the sword arm swaps the katana to the off hand, losing both arms disables attacking. **Toppling**: losing a leg costs the footing — the body tips about the feet toward the missing leg's side as an inverted pendulum (`Player::fallSide`/`fallTilt`, rendered via `SamuraiPose::bodyRoll`) until it lies on the floor (thud + blood smear). Downed fighters can't jump, crawl at a fraction of move speed set by remaining arms (`kCrawlSpeed`), and can still swing — all hit-test geometry (blade pivot/arc, limb and torso boxes) is transformed by each body's roll via `modelToWorld`/`rollLocal`/`rollHalfExtent`, so a prone chop becomes a ground sweep and a prone defender is hit where they lie. When facing flips while down, `fallSide` negates too so the world-space lie direction is preserved. `Physics::setCharacterProne` swaps the capsule to a squat one so opponents can step over the body. **Blood**: every connect bursts ballistic `BloodParticle` droplets from the wound (pure math, no Jolt; bigger burst on dismember); a droplet reaching the ground — or a debris impact near y = 0 from `debrisImpacts()` — stamps a `BloodMark` floor splat (capped ring buffer, oldest recycled; marks carry per-mark y jitter + random yaw, and main draws them under the blob shadows). **Blood (the win condition)**: each fighter has a `Player::blood` pool (max 100). Costs are deliberately stingy (torso hit 3, severed limb 8, stumps drain 0.25/s each) so attrition is slow background pressure — **beheading is the intended execution** and empties the pool instantly; a limbless fighter does bleed out eventually, but you're meant to finish them. Empty = dead: the corpse collapses through the existing topple path (`Game::collapse` seeds `fallSide` if still standing), takes no further input, and `Game::winner()`/`over()`/`overTime()` expose the outcome (decided once — post-match deaths, e.g. the winner bleeding out or corpse chops, can't flip it; corpses can still be dismembered). Attack input is edge-triggered and latched in main so presses aren't lost between fixed steps (GLFW sticky input modes are on for the same reason).
- `src/bot.hpp/.cpp` — enemy AI: a `Bot` outside the sim that reads the public `Game` state each fixed step and emits a `PlayerInput` for player 2 (main calls `bot.think` inside the fixed-step loop; re-seeded per match). Mode machine re-rolled every ~0.25–0.7 s (approach 60% / strafe 25% / retreat 15%): holds a strike band scaled off its own reach stat, steers into the foe's depth lane (strafing jinks instead), occasionally hops in from range, and reacts to a foe windup in range with a ~25% chance to raise its guard (holds block ~0.3–0.6 s) or ~30% to back off. A successful catch drops its guard and counters immediately — the riposte window bypasses its attack cooldown. Swings when lined up, gated by a randomized 0.35–1.1 s cooldown — the cooldown is the difficulty knob. Mostly light attacks; commits to the heavy mainly when the foe is in hitstun or downed (rare greedy read otherwise) and jabs when uncomfortably close.
- `src/physics.hpp/.cpp` — Jolt wrapper (pimpl; Jolt headers only in the .cpp). Owns the `PhysicsSystem`, invisible static arena colliders (ground + 4 walls — side walls placed at the ctor's per-level `arenaHalfWidth`, depth fixed; the ground is one flat slab unless the ctor gets per-level `groundBoxes` (Hanami's carved stream channel); these replaced the old position clamp — plus any per-level `StaticBox` obstacles, e.g. Hanami's stones/trunks/house; same layer as the arena so fighters and debris collide with them), an optional `Water` volume (per-step buoyancy/drag/current on debris via `ApplyBuoyancyImpulse` before the world update), and one `CharacterVirtual` capsule per fighter (radius = `kHalfWidth`, height = 2·`kHalfHeight`, origin at the feet; `Player::pos` is capsule pos + half height in y). Fighter-vs-fighter solidity comes from `CharacterVsCharacterCollisionSimple`. `moveCharacter` does `SetLinearVelocity` + `ExtendedUpdate`; `step` runs the rigid-body world (arena statics + severed-limb debris boxes; a `DEBRIS` object layer collides with the world, other debris, and the fighters — the `CharacterVirtual` update shoves the much lighter limb bodies aside, so players kick severed pieces around by walking into them). A `ContactListener` (mutex-guarded — Jolt calls it from job threads) records debris contacts above a 2 m/s closing-speed threshold; `debrisImpacts()` exposes them (full contact point + closing speed) per step and Game turns them into thud sound cues and, for ground contacts, blood smears. Jolt is pinned at v5.6.0, dynamic CRT, demos/tests off (see CMakeLists).
- `src/audio.hpp/.cpp` — miniaudio wrapper (pimpl, same pattern as Physics; falls back to silent if no device). All SFX PCM is **synthesized at startup** (no asset files): swing whoosh (bandpassed noise, swell timed so it peaks as the blade goes active), hit (pitch-dropping thud + crack), dismember (deeper thud + slice band), thud (severed limb landing; dull, no crack). Event flow: `Game::update` pushes `SoundCue{Sfx, x, gain}` into a list (swing on attack start, hit/dismember on connect, thud from `Physics::debrisImpacts()` with gain scaled by impact speed); main drains it once per render frame via `soundCues()`/`clearSoundCues()`, panning by world x against the fighters' midpoint and adding per-play pitch jitter. Each effect has a small round-robin voice pool (own `ma_audio_buffer` cursors over shared PCM) so overlapping plays don't cut each other off. **Music** is synthesized at startup too: three seamless loop tracks (`Music::Menu` plus one per battleground, ordered after Menu to match the level roster — `levelMusic(levelIndex)` maps index → track) composed from a small procedural toolkit (Karplus-Strong koto/shamisen plucks, taiko, stick, inharmonic bells, breathy flute; notes write additively with wraparound so ring-out tails cross the loop seam). Menu: sparse in-scale (E F A B C) solo koto over a temple bell at 72 BPM; Dojo: taiko pattern under a tense E–F shamisen ostinato at 100 BPM; Hanami: yo-scale (D E G A B) koto arpeggios, bell glints, flute at 84 BPM. `Audio::playMusic(track)` is an idempotent "this should be the music now" (no-op if already playing, else ~0.7/0.9 s crossfade via miniaudio sound fades) — main calls it once per frame keyed off `AppState` (front-end ⇒ Menu theme, match ⇒ `levelMusic(game->level())`), so transitions fall out of state changes; Rematch keeps the track running uninterrupted. miniaudio is pinned at 0.11.23 with `MINIAUDIO_NO_EXTRA_NODES`.
- `src/camera.hpp/.cpp` — `FramingCamera`: follows the fighters' midpoint, zooms out so both always fit the frustum (with margin), accounting for each fighter's depth; exponential smoothing
- `src/renderer.hpp/.cpp` — all Vulkan state; API is `beginFrame` / `setViewProj` / `drawBox(model, color)` / `endFrame`. Also owns the Dear ImGui integration (context + GLFW/Vulkan backends, dynamic rendering path, own small descriptor pool): `beginFrame` starts an ImGui frame, `endFrame` records the draw data before `vkCmdEndRendering`, so callers just emit ImGui widgets between the two. ImGui is pinned at v1.92.1, built as a static lib from FetchContent sources (no upstream CMake); `imgui.ini` persistence is disabled.
- `src/samurai.hpp/.cpp` — procedural samurai model: ~25 boxes (hakama legs, kimono torso, obi, sode, arms, head, kasa, sheathed katana) with stride/idle/jump animation driven by `SamuraiPose`. Severable parts are indexed 0..4 (arm +z, arm −z, leg +z, leg −z, head; must match game.hpp's `Limb`): `SamuraiPose::severed` draws stumps instead, `samuraiLimbBounds` exposes each limb's local AABB (gameplay hit regions + debris shapes), `drawSeveredLimb` draws a detached limb under a rigid-body transform
- `shaders/` — GLSL, compiled to SPIR-V at build time by glslc into `build/shaders/`

## Current conventions (early, expected to change)

- World space: x right, y **up**, z toward the camera, ground surface at y = 0, units ~meters. Camera looks down -Z from +Z; gameplay is side-focused but movement is full 3D.
- GLM is compiled with `GLM_FORCE_DEPTH_ZERO_TO_ONE` + `GLM_FORCE_RADIANS`; `FramingCamera::proj` flips Y for Vulkan clip space.
- Everything renders as a shaded unit cube generated in the vertex shader from `gl_VertexIndex`; models may rotate (normal matrix travels in push constants). `ObjectPush` is exactly 128 bytes — the guaranteed push-constant minimum — and must match `shaders/cube.vert`; do not grow it.
- Depth: single D32 depth image shared by frames in flight, transitioned from UNDEFINED each frame.
- Shaders are loaded via the `SHADER_DIR` compile definition (absolute path into the build tree) — dev-only scheme.
- `src/` is on the include path, so headers are included relative to it (`"game.hpp"`, `"levels/level.hpp"`) — no `../` paths from subdirectories.
