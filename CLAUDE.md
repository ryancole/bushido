# bushido

Side-view 3D sword PvP game (1v1). C++20, Vulkan 1.3 (dynamic rendering, sync2), GLFW, vk-bootstrap, GLM, Jolt Physics, miniaudio, Dear ImGui. Dependencies come in via CMake FetchContent; the Vulkan SDK is installed at `C:\VulkanSDK\1.4.350.0`.

## Build (Windows, MSVC + Ninja)

The toolchain is pinned to MSVC via CMakePresets.json (`msvc-debug` → `build/`, `msvc-release` → `build-release/`); CMakeLists errors out on any other Windows compiler. MSVC is not on PATH; chain through vcvars64:

```
cmd /s /c '"C:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat" && cmake --preset msvc-debug && cmake --build --preset msvc-debug'
```

Run: `build\bushido.exe`. Boots to a main menu (Play / Quit, mouse or ImGui keyboard nav); Play opens a character-select screen (mouse-driven, two stages: hovering a tile previews stats, clicking a fighter opens the weapon row, clicking a blade locks the loadout and starts the match against a randomly drawn opponent — fighter and weapon both random). Esc backs out one level (match → menu, select → menu, menu → quit). In a match — WASD moves in the ground plane (W/S = depth), Space jumps, and the mouse attacks: **left-tap = normal swing, left hold-and-release = heavy swing, right press = quick jab**; the opponent is bot-driven (see `src/bot`).

VS Code: `.vscode/` has a default build task (Ctrl+Shift+B), a `configure` task, and F5 debug configs (`cppvsdbg`). IntelliSense reads `build/compile_commands.json`.

## Layout

- `src/main.cpp` — game loop (fixed 120 Hz timestep), input reading, scene drawing. Owns the `AppState` machine (`Menu` → `CharacterSelect` → `Playing`, Esc backs out one level): menus freeze the sim (accumulator zeroed) but keep drawing the arena behind the UI; ImGui menu code (`setupMenuStyle`/`drawMainMenu`/`drawCharacterSelect` — restyled colors, Georgia from the system fonts when present, per-widget sizing via `ImGui::PushFont(nullptr, size)`) lives here, built between `beginFrame`/`endFrame`. The select screen is single-player and mouse-driven: a tile row where hovering previews a character's stats in the panel below (crimson frame follows the preview) and clicking picks it; the opponent's roster index is drawn at random (`std::mt19937` in main). `Game` is heap-owned and **rebuilt from the two (character, weapon) index pairs on pick** — every match starts fresh; the initial instance is just the diorama behind the menu. Attack input: LMB attacks on **release** — a tap is the light swing, a hold ≥ `kHeavyHoldTime` (0.28 s) charges the heavy — and RMB jabs on press; the resulting `AttackKind` is latched alongside the press so it survives zero-step frames. On match start the button latches are re-seeded from live state and a still-held LMB is flagged suppressed so even the picking click's later release doesn't become a swing (`startMatch` lambda, shared by pick and rematch). In-match HUD: `drawBloodBars` paints a blood bar per fighter into the foreground draw list (top corners, draining outward). When `Game::over()`, the bot's input is zeroed (the human keeps control) and after a 1.2 s beat `drawWinOverlay` shows VICTORY/SLAIN with Rematch (same pairing, fresh `Game`) and Character Select buttons.
- `src/character.hpp/.cpp` — the selectable roster (`CharacterDef`: stable `id` slug, name, `CharacterStats`, `SamuraiColors`, authored 0–5 select-screen ratings). All stats are compile-time constants and a match is fully described by two (character, weapon) index pairs — **multiplayer-ready by construction**: peers would only ever exchange indices/ids, never stats, keeping the sim deterministic across machines. Current four: Ronin (baseline — the old global constants), Shinobi (fast/light), Oni (slow, huge knockback, heavy), Kensei (longest reach). Stats: moveSpeed, jumpVelocity, windup/active/recovery times, reach (blade tip from shoulder — drives both the gameplay sweep and the drawn blade length via `SamuraiPose::reach`), knockback dealt, weight (divides knockback/pop received).
- `src/weapon.hpp/.cpp` — the sword loadout armory (`WeaponDef`), same compiled-in-roster contract as characters. Weapons modify the wielder rather than replace their stats: `swingScale` multiplies windup/active/recovery, `reachBonus` adds meters of blade, `knockbackScale` multiplies shove dealt, `damage` scales the torso-hit and sever blood costs (never the beheading — the execution empties the pool with any blade), `bladeWidth` is a visual-only thickness cue (`SamuraiPose::bladeWidth`). Current three: Katana (neutral — all 1×, so character tuning is unchanged), Wakizashi (fast, short, cheap cuts), Odachi (slow, long, ruinous). `Game` bakes weapon into character once in its ctor; everything outside the sim (bot, rendering) reads the resolved numbers via `Game::stats(i)`, never the raw roster.
- `src/game.hpp/.cpp` — simulation: two `Player`s moving freely in the x/z ground plane. Gameplay stays authored (Game decides velocities: move speed, jump, gravity integration into `vy`, knockback — the per-fighter numbers come from each player's `CharacterDef` with their `WeaponDef` applied, both picked at select time); collision is delegated to `Physics` per fixed step, which returns resolved position + grounded. Sword combat: `AttackState` machine (windup → active → recovery, durations per character) crossed with an `AttackKind` (light / heavy / jab) picked at press time — `kAttackTuning` in game.cpp scales the wielder's resolved phase times, damage, knockback, and hitstun per kind and sets the blade arc (light/heavy chop overhead-to-front, the jab snaps a short arc to horizontal; angles mirrored in samurai.cpp's `swordArmAngle`). The jab pierces instead of cutting: `canSever = false` downgrades any limb/head connect to a torso-grade hit — no dismemberment, no execution. During active the blade is swept as a segment along the attack's arc (pure math on `Player::pos`, not Jolt queries) against per-limb AABBs (`samuraiLimbBounds` + per-limb pad) and a torso box. Any connect ⇒ hitstun + planar knockback + upward pop + interrupts the victim's swing; a limb connect also **dismembers**: the limb is flagged in `Player::severed[]`, launched as a Jolt debris body (`SeveredPiece` list, drawn by main), and stays lost for the match. The head's z pad is tight so beheading takes depth-aligning the blade lane (sword arm rides `kShoulderSide` off center); losing the sword arm swaps the katana to the off hand, losing both arms disables attacking. **Toppling**: losing a leg costs the footing — the body tips about the feet toward the missing leg's side as an inverted pendulum (`Player::fallSide`/`fallTilt`, rendered via `SamuraiPose::bodyRoll`) until it lies on the floor (thud + blood smear). Downed fighters can't jump, crawl at a fraction of move speed set by remaining arms (`kCrawlSpeed`), and can still swing — all hit-test geometry (blade pivot/arc, limb and torso boxes) is transformed by each body's roll via `modelToWorld`/`rollLocal`/`rollHalfExtent`, so a prone chop becomes a ground sweep and a prone defender is hit where they lie. When facing flips while down, `fallSide` negates too so the world-space lie direction is preserved. `Physics::setCharacterProne` swaps the capsule to a squat one so opponents can step over the body. **Blood**: every connect bursts ballistic `BloodParticle` droplets from the wound (pure math, no Jolt; bigger burst on dismember); a droplet reaching the ground — or a debris impact near y = 0 from `debrisImpacts()` — stamps a `BloodMark` floor splat (capped ring buffer, oldest recycled; marks carry per-mark y jitter + random yaw, and main draws them under the blob shadows). **Blood (the win condition)**: each fighter has a `Player::blood` pool (max 100). Costs are deliberately stingy (torso hit 3, severed limb 8, stumps drain 0.25/s each) so attrition is slow background pressure — **beheading is the intended execution** and empties the pool instantly; a limbless fighter does bleed out eventually, but you're meant to finish them. Empty = dead: the corpse collapses through the existing topple path (`Game::collapse` seeds `fallSide` if still standing), takes no further input, and `Game::winner()`/`over()`/`overTime()` expose the outcome (decided once — post-match deaths, e.g. the winner bleeding out or corpse chops, can't flip it; corpses can still be dismembered). Attack input is edge-triggered and latched in main so presses aren't lost between fixed steps (GLFW sticky input modes are on for the same reason).
- `src/bot.hpp/.cpp` — enemy AI: a `Bot` outside the sim that reads the public `Game` state each fixed step and emits a `PlayerInput` for player 2 (main calls `bot.think` inside the fixed-step loop; re-seeded per match). Mode machine re-rolled every ~0.25–0.7 s (approach 60% / strafe 25% / retreat 15%): holds a strike band scaled off its own reach stat, steers into the foe's depth lane (strafing jinks instead), occasionally hops in from range, and has a ~45% chance to back off when the foe starts a windup in range. Swings when lined up, gated by a randomized 0.35–1.1 s cooldown — the cooldown is the difficulty knob. Mostly light attacks; commits to the heavy mainly when the foe is in hitstun or downed (rare greedy read otherwise) and jabs when uncomfortably close.
- `src/physics.hpp/.cpp` — Jolt wrapper (pimpl; Jolt headers only in the .cpp). Owns the `PhysicsSystem`, invisible static arena colliders (ground slab + 4 walls at the arena bounds — these replaced the old position clamp), and one `CharacterVirtual` capsule per fighter (radius = `kHalfWidth`, height = 2·`kHalfHeight`, origin at the feet; `Player::pos` is capsule pos + half height in y). Fighter-vs-fighter solidity comes from `CharacterVsCharacterCollisionSimple`. `moveCharacter` does `SetLinearVelocity` + `ExtendedUpdate`; `step` runs the rigid-body world (arena statics + severed-limb debris boxes; a `DEBRIS` object layer collides with the world, other debris, and the fighters — the `CharacterVirtual` update shoves the much lighter limb bodies aside, so players kick severed pieces around by walking into them). A `ContactListener` (mutex-guarded — Jolt calls it from job threads) records debris contacts above a 2 m/s closing-speed threshold; `debrisImpacts()` exposes them (full contact point + closing speed) per step and Game turns them into thud sound cues and, for ground contacts, blood smears. Jolt is pinned at v5.6.0, dynamic CRT, demos/tests off (see CMakeLists).
- `src/audio.hpp/.cpp` — miniaudio wrapper (pimpl, same pattern as Physics; falls back to silent if no device). All SFX PCM is **synthesized at startup** (no asset files): swing whoosh (bandpassed noise, swell timed so it peaks as the blade goes active), hit (pitch-dropping thud + crack), dismember (deeper thud + slice band), thud (severed limb landing; dull, no crack). Event flow: `Game::update` pushes `SoundCue{Sfx, x, gain}` into a list (swing on attack start, hit/dismember on connect, thud from `Physics::debrisImpacts()` with gain scaled by impact speed); main drains it once per render frame via `soundCues()`/`clearSoundCues()`, panning by world x against the fighters' midpoint and adding per-play pitch jitter. Each effect has a small round-robin voice pool (own `ma_audio_buffer` cursors over shared PCM) so overlapping plays don't cut each other off. miniaudio is pinned at 0.11.23 with `MINIAUDIO_NO_EXTRA_NODES`.
- `src/camera.hpp/.cpp` — `FramingCamera`: follows the fighters' midpoint, zooms out so both always fit the frustum (with margin), accounting for each fighter's depth; exponential smoothing
- `src/renderer.hpp/.cpp` — all Vulkan state; API is `beginFrame` / `setViewProj` / `drawBox(model, color)` / `endFrame`. Also owns the Dear ImGui integration (context + GLFW/Vulkan backends, dynamic rendering path, own small descriptor pool): `beginFrame` starts an ImGui frame, `endFrame` records the draw data before `vkCmdEndRendering`, so callers just emit ImGui widgets between the two. ImGui is pinned at v1.92.1, built as a static lib from FetchContent sources (no upstream CMake); `imgui.ini` persistence is disabled.
- `src/samurai.hpp/.cpp` — procedural samurai model: ~25 boxes (hakama legs, kimono torso, obi, sode, arms, head, kasa, sheathed katana) with stride/idle/jump animation driven by `SamuraiPose`. Severable parts are indexed 0..4 (arm +z, arm −z, leg +z, leg −z, head; must match game.hpp's `Limb`): `SamuraiPose::severed` draws stumps instead, `samuraiLimbBounds` exposes each limb's local AABB (gameplay hit regions + debris shapes), `drawSeveredLimb` draws a detached limb under a rigid-body transform
- `shaders/` — GLSL, compiled to SPIR-V at build time by glslc into `build/shaders/`

## Current conventions (early, expected to change)

- World space: x right, y **up**, z toward the camera, ground surface at y = 0, units ~meters. Camera looks down -Z from +Z; gameplay is side-focused but movement is full 3D.
- GLM is compiled with `GLM_FORCE_DEPTH_ZERO_TO_ONE` + `GLM_FORCE_RADIANS`; `FramingCamera::proj` flips Y for Vulkan clip space.
- Everything renders as a shaded unit cube generated in the vertex shader from `gl_VertexIndex`; models may rotate (normal matrix travels in push constants). `ObjectPush` is exactly 128 bytes — the guaranteed push-constant minimum — and must match `shaders/cube.vert`; do not grow it.
- Depth: single D32 depth image shared by frames in flight, transitioned from UNDEFINED each frame.
- Shaders are loaded via the `SHADER_DIR` compile definition (absolute path into the build tree) — dev-only scheme.
